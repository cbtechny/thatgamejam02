# 全游戏完成计划

更新：2026-11-06。目标是完整成品体验，覆盖玩法、内容、视听、流程与发布质量。以下均为待完成／待验证；存在原型和自动测试不等于验收完成。

建议分工：Chris 负责程序与构建；Lilith 负责美术与文案；Packy 负责整合、技术美术、动画及验收。分工待团队确认，本文不虚构时间承诺。

## A. 锁定制作依据

- [ ] A1｜Packy + Chris：逐关试玩并录下入场、操作、失败、成功全流程，产出逐关问题表，标明功能、可读性、视觉、声音问题。
- [ ] A2｜Packy + Lilith：制作开场、两次关间衔接、终场的简短分镜。每段写明画面、文案、动作、音效、音乐与输入开放时机。终场以音乐盒全景为基础。
- [ ] A3｜全员：建立素材交接表，每项写清文件名、使用位置、尺寸／透明边界、锚点、图层、动画帧或时长、负责人、状态。先以实际关卡截图确定构图，再制作正式图。

完成标准：程序无需猜测素材用途，美术无需猜测布局；每个玩家可见状态都有明确制作内容。

## B. 完成统一流程

建议负责人：Chris；Packy 配合演出。依赖 A1、A2。

- [ ] B1｜接通第一关入锁后到第二关、第二关送达后到第三关、第三关到终场。成功只触发一次；继续与切关前解除暂停；第一关不再显示整款游戏结束的文案。
- [ ] B2｜所有关卡统一 Esc 暂停、继续、重试、返回标题；暂停冻结波浪、跳跃及相关计时，恢复后保持正确状态。
- [ ] B3｜重试和退出清理碎片位置、失败状态、风扇、拖拽、声音、成功界面与演出回调；返回标题再开始从第一关初始状态进入。
- [ ] B4｜提示说明本关转柄作用和 Space 功能；第一关在需要时提示接取。按钮焦点明确，入场和成功时不误触谜题。
- [ ] B5｜标题／终场提供制作名单、返回、重新开始；提供基本音乐／音效音量设置，并在同次运行中保留。

验收：从 Main 连续完成三关到署名，不借助编辑器；在入场、动作中、失败、成功时分别检查暂停、重试、退出、失焦恢复。

## C. 完成关卡可读性与难度

建议负责人：Packy 组织试玩，Chris 调整参数，Lilith 完善视觉信息。

- [ ] C1｜第一关：陌生玩家能区分转柄抬升、Space 释放、接取三阶段；漏接原因可理解；拼合入锁可见、无跳变，重试迅速。
- [ ] C2｜第二关：用画面与简短提示表达水位、漂浮和高度关系，让玩家理解风扇选择前方第一个可达目标，避免误以为可以自由瞄准。
- [ ] C3｜第二关实玩：验证固定风程提示、木板循环、落地时机和失败后重试节奏。
- [ ] C4｜第三关实玩：验证灯塔扫光时能读出漂木的位置和方向，检查防波堤前后的跳跃窗口。
- [ ] C5｜至少一位未参与实现的人在无口头讲解下完成全程；记录首次卡点、误解和恢复行为，修正后复测。

验收：试玩记录能解释玩家如何理解与解决谜题；不能只记录“通关了”。正式美术接入后再测一次。

## D. 完成全部视觉与动画

建议负责人：Lilith 主美术，Packy 主动画与技术美术，Chris 接入状态。布局依赖 A3，可与 B 并行。

| 位置 | 制作交付物 | 验收标准 |
| --- | --- | --- |
| 标题 | 最终标题字样、按钮、幕布、音乐盒构图 | 无占位文字、遮挡和拉伸；开始操作明确 |
| 第一关 | 绳索／风扇／碎片统一，高亮、提示排版、拼合入锁收尾 | 各阶段提示正确，关键动作可见 |
| 第二关 | 海洋背景、水面、起点、浮木、岩石、高处目标与锁孔 | 无占位几何；轮廓与脚本落点一致；水位变化清楚 |
| 第三关 | 海洋资产夜色变体、柔光、碎片灯、长路线构图 | 暗而可读，关键平台不因照明消失 |
| 第二三关成功 | 碎片送达／入锁、目标反馈、继续入口 | 成功含义清楚，演出前停止谜题输入；不新增三片拼合机制 |
| 关间转场 | 两次衔接的缩放／幕布及声音时序 | 构图连贯，输入锁定准确，无黑屏卡住 |
| 终场 | 音乐盒完成状态、机关／光效动画、结束文案、署名 | 有明确收束，可返回或重开，无下一关残留 |
| 通用 UI | 提示、暂停、失败、成功、按钮、音量控件 | 字体、字号、语气一致；小窗口仍可读 |

- [ ] D1｜按上表建立实际素材条目与制作状态，逐项交接和接入。
- [ ] D2｜核对正式素材透明留白、锚点、层级、裁切、脚本落点；保留编辑源文件，与运行资产分开管理。
- [ ] D3｜逐场检查入场、静止、动作、失败、成功和退出画面，确认没有临时几何、调试文字或未完成视觉内容。

## E. 完成音乐与声音

建议负责人：Packy 统筹，Chris 接入，各素材提供者确认来源。

- [ ] E1｜制定标题、三关、成功、转场、终场音乐表，明确播放与停止时机。确认主题录音授权限制，不能默认允许剪辑或重编排。
- [ ] E2｜试听转柄、风扇启停／循环、落地、接取、无效操作、失败、成功、UI；修复缺音、突切、叠加和音量不均。
- [ ] E3｜验证暂停、失焦、重试、返回标题、重复切关时声音行为；音乐不盖住关键反馈，静音与音量设置生效。
- [ ] E4｜用耳机和普通扬声器各试听完整流程，终场结束后菜单仍可操作。

验收：音乐支持三关情绪递进和最终收束，不仅有动作音效；实际试听通过。

## F. 最终集成与发布

建议负责人：Chris 构建，Packy 验收和提交资料，全员核对署名。

- [ ] F1｜确认本地 3D 工作、项目配置和导入配置的归属，明确最终包依赖；不误覆盖实验工作，也不将其自动替换为主入口。
- [ ] F2｜重跑三关现有回归脚本，记录版本、命令、结果；检查连续切关、成功重复触发、暂停泄漏和重复完整游玩。
- [ ] F3｜检查 1920×1080 及较小窗口下的文字、按钮、鼠标命中和舞台裁切；处理控制台错误。
- [ ] F4｜配置目标桌面平台导出，生成候选包；在不依赖编辑器的环境完整游玩，确认资源、音频、输入与退出正常。
- [ ] F5｜完成游戏名、简介、操作说明、截图、署名、素材许可记录、AI 使用披露；提交前核对官方截止时间和上传要求。
- [ ] F6｜最终修复后重验受影响流程，生成并标记最终构建，确保上传包就是验收过的包。

## 执行顺序与完成门槛

A 确定玩法、分镜和规格 → B 流程整合与 D 素材制作并行 → C 持续试玩调整 → D、E 全量接入 → F 对导出包验收。

完成意味着：三关规则清楚，流程闭合，所有玩家可见内容完成，视听统一，失败可恢复，终场有收束，发布包经过完整人工验证。自动测试通过和三关能通关是必要条件，不能代替上述内容完成。

本轮不新增第二把发条、额外关卡或整套 3D 迁移；若发现现有三关必须改规则才能成立，先记录具体试玩证据，再调整方案与任务。
